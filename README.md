# 3x-ui-stealth

Однофайловый установщик скрытого VPN-узла: **3x-ui за nginx на подставном домене**.
Панель живёт только на localhost, наружу торчит один порт 443 с обычным сайтом-заглушкой,
подключение — VLESS + WebSocket + TLS. В конце скрипт печатает доступы к панели,
ссылку `vless://…` и QR-код прямо в терминале.

По мотивам руководства
[«Полное руководство по установке и настройке панели 3X-UI»](https://telegra.ph/Polnoe-rukovodstvo-po-ustanovke-i-nastrojke-paneli-3X-UI-11-20).

## Возможности

- одна команда на чистую Ubuntu 22.04/24.04 или Debian 12 — больше ничего делать не нужно;
- 3x-ui ставится неинтерактивно: случайные логин/пароль/порт/секретный webPath;
- панель привязана к `127.0.0.1`, наружу доступна только через nginx по webPath;
- VLESS+WS создаётся через API 3x-ui, TLS терминирует nginx сертификатом Let's Encrypt;
- в инбаунд добавляется **Хост** (домен:443, TLS, SNI, fingerprint) и клиенту назначается
  `subId` — панель генерирует правильные ссылки `vless://` и QR без ошибок;
- сайт-заглушка (шаблон Aerial с html5up) для всех, кто пришёл не по секретным путям;
- nginx слушает **только IP домена** — сертификат не светится на остальных IP сервера;
- сервер подписок 3x-ui (порт 2096) отключается;
- HSTS не включается нигде: ни в nginx, ни в панели (`XUI_SKIP_HSTS=1` + `proxy_hide_header`);
- автопродление сертификата штатным `certbot.timer` + deploy-хук с reload nginx;
- hostname и домен проверяются только по внешнему DNS (`dig @1.1.1.1`/`8.8.8.8`), минуя
  `/etc/hosts` — локальная связка не может подсунуть основной IP вместо A-записи;
- если hostname сервера уже резолвится в его IP — предлагается как домен по умолчанию;
- после выбора домена из `/etc/hosts` удаляется связка `домен → IP` (для системных
  резолверов; образы VPS прописывают там основной IP, мешая честному резолву);
  перед правкой создаётся бэкап с уникальным именем `/etc/hosts.bak.3xui.<дата>.<pid>`;
- если домен указывает на основной IP — предупреждение с рекомендацией вторичного;
- доступы и ссылка подключения сохраняются в `/root/3x-ui-access.txt` (chmod 600).

## Требования

- чистый VPS: Ubuntu 22.04/24.04 LTS или Debian 12, доступ root по SSH;
- домен (можно выданный хостером технический), A-запись которого указывает на IP сервера;
- порт 80 открыт для проверки Let's Encrypt, порт 443 — для трафика;
- повторный запуск на уже установленной 3x-ui запрещён (сначала `x-ui uninstall`).

## Быстрый старт

```bash
bash <(curl -Ls https://raw.githubusercontent.com/porutchik/3x-ui-stealth/main/setup-3xui.sh)
```

или через пайп (вопросы читаются с `/dev/tty`, так что и так работает):

```bash
curl -Ls https://raw.githubusercontent.com/porutchik/3x-ui-stealth/main/setup-3xui.sh | bash
```

Скрипт спросит:

1. **подставной домен** (Enter — hostname сервера, если он резолвится в его IP);
2. подтверждение, если домен указывает на основной IP (порекомендует вторичный).

Неинтерактивный режим — для автоматизации:

```bash
setup-3xui.sh -d example.com -c myclient -y
```

| Флаг | Значение |
|------|----------|
| `-d DOMAIN` | домен (обязателен в неинтерактивном режиме) |
| `-c NAME`   | имя клиента/подключения (по умолчанию `main`) |
| `-y`        | не задавать вопросов (продолжать с основным IP и т.п.) |

```text
 Панель 3x-ui:
   адрес:   https://example.com/<webPath>/
   логин:   xolJuuV8Sq
   пароль:  PLixLxqB9Kl8DZkp

 Подключение VLESS (main):
   vless://<uuid>@example.com:443?encryption=none&security=tls&sni=example.com&fp=chrome&type=ws&host=example.com&path=%2F<путь>#main
```

Ссылку можно вставить в любой клиент: v2rayN / Nekoray / Hiddify / Streisand / v2rayNG /
Happ — или отсканировать QR с экрана терминала.

## Как это устроено

```text
                         Интернет
                            │
                ┌───────────▼────────────┐
                │   nginx  :80  :443     │   слушает ТОЛЬКО IP домена
                │   сертификат LE, h2    │   HSTS не включён
                └──┬──────────┬────────┬─┘
                   │          │        │
        /           │   /webPath/  │   /<ws-путь>
   сайт-заглушка   │              │        │
   (html5up Aerial)│              │        │ if ($http_upgrade != "websocket") { return 404; }
                   │              │        │
          301 → https   ┌────────▼───┐ ┌──▼──────────────┐
                       │   3x-ui    │ │  xray (VLESS+WS) │
                       │ 127.0.0.1  │ │   127.0.0.1      │
                       └────────────┘ └─────────────────┘
```

- наружу открыт один порт 443 (и 80 для ACME/редиректа); всё остальное — localhost;
- панель отвергает запросы с чужим Host (в настройках задаётся `webDomain`);
- не-websocket запросы на WS-путь получают 404, как у обычного сайта.

## Сертификат и автопродление

Выпуск — `certbot certonly --webroot` (nginx не останавливается, конфиг не правится).
Продление — системный `certbot.timer` дважды в сутки запускает `certbot renew`;
хук `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` перезагружает nginx,
чтобы тот подхватил обновлённый сертификат. Проверка: `certbot renew --dry-run`.

## Файлы

| Путь | Что это |
|------|---------|
| `/etc/nginx/conf.d/selfsteal.conf` | конфиг nginx (заглушка + панель + WS) |
| `/var/www/selfsteal/` | сайт-заглушка |
| `/etc/x-ui/x-ui.db` | БД панели — это и есть бэкап для переноса |
| `/etc/x-ui/install-result.env` | креды/порт/webPath/API-токен (600) |
| `/etc/default/x-ui` | env сервиса (`XUI_SKIP_HSTS=1`) |
| `/root/3x-ui-access.txt` | сводка доступов (600) |
| `/etc/letsencrypt/live/<домен>/` | сертификат |

## Управление

```bash
x-ui                 # меню панели (start/stop/restart/settings/update/…)
x-ui uninstall       # снести 3x-ui (nginx и сертификат останутся)
nano /etc/nginx/conf.d/selfsteal.conf && systemctl reload nginx
certbot delete --cert-name example.com   # если домен больше не нужен
```

При смене A-записи на другой IP сервера: поправьте `listen` в
`/etc/nginx/conf.d/selfsteal.conf`, затем `systemctl reload nginx && certbot renew --force-renewal`.

## Заметки

- Скрипт сознательно не трогает фаервол (на свежей Ubuntu ufw выключен; откройте 22/80/443 сами, если он у вас включён).
- Обновление 3x-ui — штатным способом: `x-ui update` (настройки и БД сохраняются).
- Используйте на свой страх и риск и в рамках законов вашей юрисдикции.
